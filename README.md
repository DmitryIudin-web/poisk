# Монитор Volkswagen Teramont Pro 2026

Почасовой монитор публичных предложений Volkswagen Teramont Pro 2026. Он ищет
автомобили с чёрным кузовом и чёрным салоном, DCC, максимальной комплектацией
Peak/Summit или подтверждённым эквивалентом, пробегом до 1 000 км и физическим
наличием у продавца.

Монитор не считает отсутствие данных отрицательным фактом. Неподтверждённые
характеристики сохраняются как `unknown`, а недоступная площадка — как
`source_gap`, а не как ноль предложений.

## Что проверяется

Источники разделены и опрашиваются независимо:

- Россия: Auto.ru, Drom, Avito;
- Бишкек и Кыргызстан: Mashina.kg;
- другие рынки ЕАЭС: Kolesa.kz и лоты с соответствующей географией.

Для каждого лота сохраняются доступные в источнике сведения:

- VIN;
- цена без скидок за кредит, trade-in и страхование;
- отдельно — заявленная условная цена, если безусловная не подтверждена;
- статус ЭПТС и коммерческого утильсбора для российских предложений;
- цена и валюта исходного рынка без выдуманного пересчёта «под ключ»;
- регион, пробег, комплектация, DCC и статус физического наличия.

## Уведомления

Telegram используется только для пяти событий:

1. новый полностью релевантный лот;
2. снижение подтверждённой цены в рублях минимум на 50 000 ₽;
3. появление автомобиля в наличии;
4. подтверждение критичного параметра, VIN, ЭПТС или утильсбора;
5. явная продажа/снятие либо отсутствие в двух последовательных успешных
   сканированиях площадки.

Ошибка, CAPTCHA, HTTP 403/429 или неожиданно пустая страница не увеличивает
счётчик отсутствия. Частичный обход — например, если одна карточка не открылась
или достигнут защитный лимит карточек — также не считается полным доказательством
снятия остальных лотов. Каждое уведомление содержит стабильный в рамках одного
перехода `event`-идентификатор; новый цикл «снова в наличии → снова снят» получает
новый идентификатор.

## Настройка GitHub

### 1. Разрешить запись состояния

Откройте репозиторий → **Settings → Actions → General → Workflow permissions** и
выберите **Read and write permissions**. Это нужно только для отдельной ветки
`monitor-state`, где хранится история. Кодовая ветка автоматически не изменяется.

### 2. Добавить ровно два GitHub Secrets

Откройте **Settings → Secrets and variables → Actions → New repository secret** и
добавьте:

| Secret | Содержимое |
|---|---|
| `TELEGRAM_BOT_TOKEN` | токен бота от BotFather |
| `TELEGRAM_CHAT_ID` | числовой ID личного чата, группы или канала |

Не добавляйте токен в `sources.json`, README, workflow, команды Git или файлы
состояния. Чтобы бот мог писать в группу/канал, добавьте его туда с правом
публикации. Перед использованием личного чата отправьте боту хотя бы одно
сообщение.

### 3. Первый запуск

После появления кода в основной ветке откройте **Actions → Volkswagen Teramont
Pro monitor → Run workflow**. Первый успешный запуск автоматически создаст ветку
`monitor-state`.

Локальный commit или наличие workflow в отдельной ветке **не запускает мониторинг**.
Расписание начинает работать только после попадания `.github/workflows/monitor.yml`
в основную ветку GitHub. Планировщик запускается каждый час на 17-й минуте UTC;
GitHub может задержать или в редких случаях пропустить запуск при высокой нагрузке.

## Локальная проверка

Требуется Python 3.12 или новее. В PowerShell:

```powershell
$env:PYTHONPATH = "src"
python -m unittest discover -s tests -t . -v
python -m teramont_monitor smoke --config config/sources.json --dry-run
```

`smoke` обращается к живым публичным страницам, но не пишет состояние и ничего не
отправляет в Telegram. Результат по каждой площадке — успешное число найденных
страниц либо конкретный `source_gap`.

Проверка на сохранённых минимальных примерах не обращается к интернету:

```powershell
$env:PYTHONPATH = "src"
python -m unittest discover -s tests -t . -v
```

## Данные и дедупликация

Ветка `monitor-state` содержит:

- `state.json` — последнее состояние лотов и счётчики отсутствия;
- `history.jsonl` — хронологию наблюдений, цен, статусов и разрывов источников;
- `pending-events.json` — события, ожидающие подтверждённой доставки.

Ключ объявления строится из площадки и её ID, затем из канонической ссылки.
Одинаковый VIN дополнительно объединяет предложения разных продавцов на уровне
автомобиля, не стирая различия в цене и местонахождении. Поэтому два объявления
с одним VIN остаются двумя предложениями, но не создают два одинаковых уведомления
«новый лот».

В репозиторий и историю не записываются токены, cookies, исходные HTML-страницы,
телефоны или контакты продавцов.

## Изменение источников

Параметры находятся в `config/sources.json`: поисковый URL, разрешённые домены,
форма ссылки на объявление, лимит карточек и пауза между запросами. Если площадка
меняет адрес или разметку, измените только её конфигурацию/адаптер и минимальный
тестовый пример. Не добавляйте обход CAPTCHA, авторизацию или прокси без отдельного
решения владельца.

## Диагностика

- `blocked` — площадка вернула защиту или CAPTCHA;
- `rate_limited` — HTTP 429 или просьба снизить частоту;
- `unexpected_empty` — страница открылась, но не содержит ни лотов, ни честного
  сообщения о пустой выдаче;
- `detail_failed` — все найденные карточки источника не прочитались;
- `detail_timeout`, `detail_blocked` и похожие коды — конкретная карточка не
  прочиталась, при этом остальные результаты источника сохранены как частичные;
- `timeout`/`network_error` — источник не ответил.

Если не сработал весь рынок, workflow сначала записывает все `source_gap` в ветку
`monitor-state`, затем завершается ошибкой и не формирует рыночное уведомление. В
GitHub Actions сохраняется только короткий очищенный диагностический JSON на 14
дней.

## Отключение и откат

Отключите workflow на вкладке Actions или удалите расписание отдельным коммитом.
Откат кода не удаляет историю. Удаление ветки `monitor-state` необратимо стирает
накопленные наблюдения и должно выполняться отдельно и осознанно.
