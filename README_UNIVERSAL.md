# Universal Vehicle Search — без Vercel

Публичный конструктор поисков автомобилей поверх методологии `poisk`.

## Что делает

1. Спрашивает марку и модель.
2. Задаёт только недостающие уточняющие вопросы: год, пробег, состояние, рынки, цвета, обязательные опции, бюджет и требование export/ex-VAT.
3. Сохраняет каждый пользовательский поиск отдельно.
4. Worker регулярно запускает поиск по выбранным рынкам.
5. Объявление становится `relevant` только когда обязательные опции подтверждены текстом карточки. Если доказательств не хватает — это `candidate`, а не ложное совпадение.
6. Дедупликация идёт по VIN, а при его отсутствии — по каноническому URL и заголовку.
7. Новые релевантные объявления и снижения цены могут уходить в Telegram.

## Архитектура

- `FastAPI` — публичный web/API;
- `SQLite WAL` — поиски, результаты и история для MVP;
- отдельный `worker` — постоянный мониторинг;
- `Bright Data SERP API` — общий discovery-слой по рынкам;
- существующие адаптеры `poisk` остаются для глубокого поиска по конкретным площадкам;
- Docker Compose — развёртывание на обычном VPS без зависимости от конкретного облачного хостинга.

## Рынки MVP

Европа, ОАЭ, Грузия, Россия, Китай, Корея, Япония, США. Для каждого рынка задан стартовый список автомобильных доменов; архитектура позволяет добавлять источники без изменения мастера и API.

## Запуск

```bash
cp .env.example .env
# заполнить BRIGHTDATA_API_KEY
# TELEGRAM_BOT_TOKEN нужен только для уведомлений

docker compose up -d --build
```

Открыть `http://SERVER_IP:8000/`.

Проверка здоровья:

```bash
curl http://SERVER_IP:8000/health
```

## Telegram

После создания поиска интерфейс показывает команду вида:

```text
/bind A1B2C3
```

Отправьте её Telegram-боту, токен которого задан в `TELEGRAM_BOT_TOKEN`. Worker привяжет `chat_id` к конкретному поиску. Публичному пользователю не нужны API-ключи или доступ к серверу.

## Источник поиска

MVP использует Bright Data SERP API для discovery и затем пытается открыть найденную карточку напрямую. Если карточка блокирует доступ, обязательная опция не считается подтверждённой. Это намеренно консервативно.

Bright Data на момент проектирования предлагает бесплатный уровень 5 000 SERP-запросов в месяц, затем pay-as-you-go. Ключ хранится только на backend.

## Ограничения MVP

- Фото пока не проходят автоматическую vision-проверку. Опция, которая видна только на фотографии и отсутствует в тексте, остаётся `unknown/candidate`.
- Общий SERP discovery не заменяет специализированные адаптеры для площадок с хорошим API или стабильной структурой.
- SQLite выбран для простого первого публичного запуска; при росте нагрузки хранилище следует заменить на PostgreSQL, сохранив API.
- Для публичного production-домена перед web-сервисом нужен reverse proxy с HTTPS (Caddy/Nginx/Traefik).

## Проверка

Локально для нового ядра выполнены unit-тесты:

- пошаговый wizard;
- отсутствие зацикливания на необязательных полях;
- evidence-gating обязательных опций;
- отсутствие ложного распознавания года как цены;
- `candidate` при неполном доказательстве;
- дедупликация результатов.

Также выполнен FastAPI smoke-test: `/health`, `/api/wizard/next`, создание поиска и чтение профиля по owner-token.
